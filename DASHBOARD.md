# StreamGuard — Dashboard Assignment

## Objective

Build a lightweight **C#/.NET dashboard** that visualizes the results of a completed StreamGuard scan.

The dashboard is a presentation layer only. It consumes the existing `report.json` and must not duplicate StreamGuard's parsing, telemetry, or threat-assessment logic.

```text
Log File
   │
   ▼
StreamGuard Console
   │
   └──► report.json
            │
            ▼
     .NET / Blazor Dashboard
```

The dashboard must be independently removable without affecting the StreamGuard analyzer.

---

## Technology

Use:

- C#
- .NET 10
- Blazor
- ASP.NET Core hosting
- `System.Text.Json`
- CSS
- A Blazor-compatible charting library if needed

Keep the dashboard within the .NET ecosystem.

Do not introduce:

- Entity Framework
- Database
- Authentication
- Cloud services
- WebSockets
- ML
- Separate Node/Express backend
- React, Angular, or Vue
- A second API/backend layer unless explicitly approved

## Architecture

The core StreamGuard application remains the source of truth.

```text
StreamGuard
    │
    │ analyzes large log
    ▼
report.json
    │
    │ consumed by
    ▼
Blazor Dashboard
```

The dashboard is responsible only for presentation.

### Dashboard may

- Load and validate JSON
- Display report values
- Transform values for presentation
- Render charts
- Render tables/cards
- Handle UI interaction
- Display errors

### Dashboard must not

- Parse log files
- Use StreamGuard security regexes
- Classify security events
- Calculate threat levels
- Calculate the failure-to-success ratio
- Implement bounded counters
- Reimplement StreamGuard analysis

`report.json` is the source of truth.

## Functional Requirements

### FR-D01 — Load Report

Load an existing `report.json` generated by StreamGuard.

Before implementation, inspect an actual generated report and use its exact property names and structure.

The dashboard must not read the original multi-gigabyte log.

### FR-D02 — Scan Summary

Display:

- File name/path
- Total lines
- Matched lines
- Execution time
- Scan timestamp

### FR-D03 — Event Distribution

Display counts for:

- Failed authentication
- Successful authentication
- Invalid-user probes
- Sudo events

Use a clear chart.

### FR-D04 — Threat Assessment

Display:

- Threat level
- Failure-to-success ratio
- Relevant event counts
- Threat explanation

Use the values already produced by StreamGuard.

The dashboard must not recalculate the threat level or ratio.

### FR-D05 — Top Usernames

Display the bounded top usernames returned by StreamGuard.

Do not reconstruct or calculate global frequencies.

### FR-D06 — Top Source IPs

Display the bounded top source IPs returned by StreamGuard.

Do not reconstruct or calculate global frequencies.

### FR-D07 — Approximation Notice

Clearly indicate that top username and source-IP statistics are bounded estimates and may be approximate after counter eviction.

Example:

> Top username and source-IP statistics are bounded estimates and may not represent exact global frequencies.

### FR-D08 — Error Handling

Handle:

- Missing `report.json`
- Invalid JSON
- Missing expected fields

Show a clear user-facing error.

### FR-D09 — Reload

Provide a simple **Reload Report** action that rereads `report.json`.

Live log monitoring is out of scope.

3. HIGH-threat data displays correctly.

## Definition of Success

The goal is not to build a sophisticated web application.

The goal is to demonstrate that:

> StreamGuard performs the analysis and produces a structured report. A separate .NET/Blazor dashboard consumes that report and presents it visually without coupling itself to the scanning engine.

Keep the implementation simple, isolated, explainable, and consistent with StreamGuard's bounded-memory and separation-of-concerns philosophy.
